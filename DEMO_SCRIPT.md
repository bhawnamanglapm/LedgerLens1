# LedgerLens — Demo walkthrough script (≈4 minutes)

Record the screen at 1440 px wide. Run the **local app** with your API key (`cd app && ANTHROPIC_API_KEY=… npm start`, open http://localhost:8787) so the LLM is live. Have the `test-statements/` folder open beside the browser. Use only the repository's synthetic statements. This is a proof of concept: its score and labels are uncalibrated, its checks do not establish statement authenticity, and it must not be presented as lending advice or a real credit decision.

| # | Time | What to click | What to say |
|---|------|---------------|-------------|
| 1 | 0:00–0:20 | Open the app on **Home**, then click **Upload a statement**. | "This is LedgerLens, a bank-statement-analysis proof of concept. Its outputs are experimental, not validated for lending; I am using synthetic data only. It shows extraction, classification and prototype risk rules, but its checks cannot prove a statement is authentic." |
| 2 | 0:20–0:50 | Point at **AI step: LLM (Claude)**, then upload `01_single_month_digital.pdf`. Point at the pipeline as each step completes. | "The model reads each batch of three pages and returns rows as JSON. The code format-checks the response and applies selected balance checks; failures retry or fall back to the rule parser. These checks can catch some inconsistencies but do not guarantee every field is correct. Page order is checked first, and account details carry between batches." |
| 3 | 0:50–1:10 | Scroll to **Data validation** and click **Show**. | "There are 22 configured checks, such as balance arithmetic, opening/closing balance comparisons, duplicates and date gaps. These checks report selected data issues; passing them does not verify authenticity or completeness." |
| 4 | 1:10–1:40 | Click **Transactions** (click **Show** on the explainer if you want to walk through it), then hover over a row's method. | "Each row has date, value date, narration, debit or credit, balance, account, month, counterparty, channel and attributes such as UPI ID, IFSC and UTR. Classification runs RULE first, then LLM, then MANUAL, and stores a confidence on every row. Refunds are kept out of income, and so are person-to-person transfers." |
| 5 | 1:40–2:10 | Upload `02_multi_month_multi_account.pdf`. Mention that the old output is cleared and moved to the Activity log. | "This file covers three months and three accounts in one upload. Each new run starts on a clean screen." |
| 6 | 2:10–2:35 | Click **Review queue** and point at the smart mode toggle. Accept one item. | "The prototype review queue prioritizes selected items using configured thresholds. This synthetic example has 6 queued items. Resolving one changes the analysis and can save a counterparty rule; it does not validate the score or make a lending decision." |
| 7 | 2:35–3:10 | Click **Risk**. Walk through the score, the six components, the EMIs and the flags. | "The prototype combines six illustrative, uncalibrated components into a score and label. This synthetic sample scores 777 and receives a REFER label under the current rules. That output is an example of the implementation, not a recommendation or validated measure of creditworthiness." |
| 8 | 3:10–3:25 | Click **Download JSON**. | "The export uses schema `ledgerlens.bsa.v1` and holds the transactions, the risk summary and the validation report." |
| 9 | 3:25–3:45 | Upload `03a_scanned_page1.png`.. | "Scans and images go through OCR first, which runs in the browser, and the confidence of the reading is recorded." |
| 10 | 3:45–4:00 | Click **Show samples**, then **Jumbled pages**. | "This configured page-order check stops this synthetic input with a clear error. Other missing or altered content may not be detected. Activity may be retained in the browser and, when connected, synced to the server. That's the current prototype." |

**Optional clips.** Ingest → Batch log → Show details: the *Extraction* column shows each batch's model rows and agreement with the rule parser. Terminal: `npm test` (110 checks in the repository suite, including a deliberately inconsistent model row being rejected; this does not establish real-statement accuracy).

**CLI clip (20 s).** Run `node cli.js ../test-statements/02_multi_month_multi_account.pdf --llm -o out.json`. It produces the same numbers as the web app.
